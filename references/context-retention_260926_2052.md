# 如何保留“最小但完整”的错题上下文

首次建立Base、裁剪范围拿不准，或历史题转对需要恢复时读本文件。流程以SKILL.md为准；下面的历史案例只说明失误机制，不移植其分数线或项目规则。

## 一、沿答题链追踪，不只沿公式引用追踪

从错误根因和要求交付的逻辑单元出发，逐项回答：

|检查层|需要保留的内容|常见误删或泄漏|
|---|---|---|
|题目要求|相关原题正文、目标范围、输出粒度、允许辅助区、可用/禁用资料范围|把完整校验缩成单行；新增“只需做这一项”的提示|
|业务判断|对象选择、渠道/SKU/年份/情景键、金额/比例口径、时点、例外与优先次序|只留下数值；删除标签；把选择条件改成直接指定正确对象|
|计算链|输入及递归依赖、共同参数、相关明细、必要前置任务、勾稽两侧的独立来源|只留最后结果；用正确汇总替代原本要重建的明细|
|计算结构|必要空白底稿、表头、行列顺序、目标位置、表名、命名区域/结构化引用|复制成值后不再联动；删行改地址；空白计算区消失|
|可见与交互条件|确实影响作答的格式、单位显示、合并、隐藏状态、数据验证和批注|把比例显示成整数；暴露隐藏标答；新增批注提示解法|
|整体环境|可能影响旧公式的表范围、名称作用域、计算设置、整列/动态引用|新增行被SUM/筛选范围纳入；共享开关变化|

保留标准：去掉该内容，会不会让旧题不可解、改变答案、省掉关键判断/计算，或改变它的错误触发条件？会则保留；不会且无明确作用则可以删除。不要为了“尽量全”复制整个无关题库，也不要为了“小”删断一条必要依赖。

空白格没有公式，并不代表没有依赖；题面可能要求模型自行重建它。INDIRECT、OFFSET、表引用、名称、隐含的跨表业务关系也不能只靠简单公式正则判定。自动提取后必须补充业务判断。

## 二、普通答对题与历史错题共用区域时

例如普通题A让模型算渠道收入，历史错题B需要用渠道收入计算利润桥：

- A的考点可以退出独立评分，但如果原来要求自行计算A，就保留其必要任务、输入和空白区；不得直接给出正确收入或更完整的解法。
- 如果A的某个无关子输出不被B使用，可以清除或恢复它。共享来源一份即可，不复制成相互独立的数据。
- 如果原任务本来就提供A的正确公式，则照原样保留。关键是还原考生当时拿到的条件，不人为增加或减少解题帮助。
- 删除A的Rubric时同步题面与评分映射；不能形成题面要求作答、评分指向已删区域的错配。维持项目要求的总规则数，但不靠拆分传播错误凑数。

优先在副本中清除无关内容并保留必要地址；如确需删整行、整列、整表，先列出所有受影响引用，保存旧新映射，重算验证后再安装。

### 正确的下游结果也可能泄漏历史答案

沿依赖链同时做正向与反向检查。例如历史题要求求收入A，新题要求用已知收入B计算B−A，再用增量计算合同金额。如果把答对的B−A或可逆推增量的合同金额填成给定资料，模型可以反解A，原取数难点就被绕过。

- 保存历史错误的整个必要计算单元，包括已答对但不可预填的前置或下游空白；这些格可不独立计分。
- 任一模型因上游历史错误而在新题中有效失分，该新题及其必要上下文进入历史并集。保留链条不等于增加独立根因计数。
- 私有参考中验证每一层确实消费前序答案；用已观察到的错误值检查影响，并在冻结前恢复正确参考。某些分支、取整、上下限会消除误差，不能预先把所有下游结果标成错。
- 依赖链逐层新增业务判断，同时保持公开口径自足。不要把正确答案、模型错值、作者的传播检查结果放进任务，或用隐含假设制造失分。

## 三、怎样保存和比较上下文

每个独立错点至少保存一份外置快照：

- 题目稳定ID、根因ID、原题正文、评分映射。
- 锚点任务文件绝对路径、SHA-256、轮次、答错模型及对应答卷证据。
- 保留区域的 `工作表!单元格/范围`、内容/公式/空白状态及“为何必要”。
- 必要的结构、名称、单位格式、可见性、辅助区约束与题目间关系。
- 原始业务来源与新增假设；原始给定资料、需要模型完成的部分、私有标答三者分开。

全文档哈希用于证明是哪份版本；工作簿加了新题后哈希改变是正常的。是否影响历史题要看逐题快照、区域差异和业务语义；不能仅凭整文件不同宣布漂移，也不能仅凭局部数值相同宣布完全保真。

比较两条路径：

1. **有效答错锚点 → 当前Base**：发现裁剪或历史累计过程中丢失的条件。
2. **当前Base → 新题候选版**：发现加题引入的修改、间接依赖和答案提示。

给差异写明“地址 / 原内容 / 新内容 / 对哪道旧题有什么影响 / 恢复或保留的理由”。即便变化在保留区域之外，也要检查是否通过公式、名称、整列引用或新题文字影响旧题。恢复后验证可解、引用、重算和必要版式；错误是否复现仍须下一轮真实测试。

若原版有歧义或泄漏，不能为了复现恢复这种缺陷。修正题意、更新标答与规则、单列新版本；不追溯用修订规则扣旧答卷。

## 五、遇到这些情形时的判断

|情形|合格处理|
|---|---|
|旧题本轮正确，Base中原始输入没变|继续比较正文、范围、前置计算、结构及新题提示；无变化就记未复现并保留历史记录。|
|原先自行计算的前置题答对了|可取消独立计分，仍保留旧题所需的待计算状态。|
|新题在同表末尾加入十行，旧题区域没改|检查整列引用、表扩展、名称和文字提示，不能仅用局部哈希放行。|
|模型一仍错，模型二转对|分别报告；检查转对原因，不宣称两模型均复现。|
|新题错五个输出，源头只是一处括号|记录一个独立根因及五个受影响输出，按冻结规则公平判分。|
|下游自身逻辑正确、继承误差仍在容差内|该条按冻结规则给分，不因上游失分自动连坐。|
|下游自身逻辑正确、继承误差已超容差|按该条冻结规则失分，记录为上游传播，保存完整失败链。|
|计划将答对的下游结果预填为资料|先检验能否逆推历史答案；会泄漏则保留必要空白或移除泄漏结果。|
|一个模型源头答错并传导，另一个源头和全链正确|承认传播对前者有效，对后者优先换用它的历史错题起点或加入新的业务判断。|
|历史题因题意遗漏被误判|保留纠错记录，退出有效错题集合；补全题意的新版本重新测试。|
|评分尚未下载成功|保留候选版和已有Base，状态写待核实；不凭页面旧结果生成新错题。|
